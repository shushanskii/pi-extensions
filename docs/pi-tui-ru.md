# Терминальный UI (перевод страницы https://pi.dev/docs/latest/tui)

`@earendil-works/pi-tui` — это компонентная система терминала, которую использует Pi. Расширения обращаются к ней, когда встроенных диалогов, уведомлений, статусного текста и виджетов не хватает для нужного взаимодействия.

Начинайте с методов `ctx.ui` из [расширения](https://pi.dev/docs/latest/extensions#interact-with-the-user). Собственный компонент стройте только тогда, когда интерфейсу нужны собственная отрисовка, клавиатурный или мышиный ввод, фокус, разметка или жизненный цикл.

## Выберите точку встраивания

| Потребность                                | Чем пользоваться                                     |
| ------------------------------------------ | ---------------------------------------------------- |
| Выбор, подтверждение, ввод, многострочный редактор | `ctx.ui.select()`, `confirm()`, `input()` или `editor()` |
| Неблокирующая обратная связь               | `ctx.ui.notify()` или `setStatus()`                  |
| Постоянный контент рядом с редактором      | `ctx.ui.setWidget()`                                 |
| Заменить шапку, подвал или редактор        | Соответствующая фабрика компонентов в `ctx.ui`       |
| Временный интерактивный экран или оверлей  | `ctx.ui.custom()`                                    |
| Своя отрисовка инструмента или записи сессии | Расширение-рендерер                                  |

Эти API там, где нужно, получают активные тему и привязки клавиш Pi. Не заводите внутри расширения второй рендерер терминала.

## Разберитесь с моделью компонентов

Компонент отрисовывает массив строк терминала для доступной ширины. При желании он может обрабатывать клавиатурный и мышиный ввод, а также обязан сбрасывать кэшированный вывод, когда меняется его состояние или зависящее от темы содержимое.

Каждая отрисованная строка должна помещаться в переданную ширину. Измеряйте видимые колонки терминала, а не длину строки: управляющие последовательности ANSI, широкие символы, эмодзи и комбинирующиеся символы меняют отображаемую ширину.

Используйте `visibleWidth()`, `truncateToWidth()`, `sliceByColumn()` и `wrapTextWithAnsi()` вместо собственной обработки ширины терминала. Pi после каждой строки сбрасывает стили и гиперссылки, поэтому применяйте стили заново к каждой отрисованной строке.

Изменив состояние компонента, сбросьте затронутый компонент и вызовите переданный `tui.requestRender()`. TUI объединяет запросы на перерисовку и обновляет терминал.

## Собирайте интерфейс из встроенных компонентов

Пакет содержит компоненты для частых разметок и элементов управления:

- `Text`, `Markdown`, `Image` и `TruncatedText` отрисовывают содержимое.
- `Container`, `VStack`, `HStack`, `Box` и `Spacer` собирают разметку.
- `Input` и `Editor` принимают текст.
- `SelectList` и `SettingsList` реализуют готовые сценарии выбора и настроек с поиском.
- `ScrollView` даёт прокручиваемое окно ограниченного размера.
- `Loader` и `CancellableLoader` показывают длительную работу.
- `MouseRegion` добавляет обработку указателя вокруг другого компонента.

Лучше использовать эти компоненты, чем заново собирать выбор, прокрутку, редактирование текста или обработку ширины. В примерах расширений показано, как сочетать их с рамками и темами Pi.

## Обрабатывайте клавиатурный ввод и фокус

Для клавиатурного ввода терминала используйте `matchesKey()` и `Key`. Анализатор учитывает поддерживаемые протоколы терминала и модификаторы. Компонентам расширений для настраиваемых действий приложения следует брать переданный `KeybindingsManager`.

Компонент, который показывает текстовый курсор, должен реализовывать `Focusable` и ставить `CURSOR_MARKER` непосредственно перед своим визуальным курсором. Оберните клетку курсора в `renderFakeCursor()`, чтобы TUI рисовал её инверсной видеографикой либо прятал после `CURSOR_MARKER`, когда показан аппаратный курсор. TUI использует маркер, чтобы разместить аппаратный курсор для методов ввода.

Контейнеры, оборачивающие `Input` или `Editor`, обязаны передавать им своё состояние `focused`. Без передачи окна кандидатов китайских, японских, корейских и других методов ввода оказываются не на своих местах.

Наследуйте `CustomEditor` от редактора Pi, когда заменяете основной редактор. Он сохраняет горячие клавиши приложения и управление агентом.

Клавиши, которые ваш редактор не перехватывает, передавайте базовой реализации; вернуть поведение по умолчанию можно, очистив фабрику произвольного редактора.

## Обрабатывайте мышиный ввод

В полноэкранном режиме нормализованные события мыши направляются компонентам. Обработчик может пометить событие обработанным, захватить перетаскивание, затребовать фокус или запросить перерисовку.

Необработанные события колеса прокручивают ближайший `ScrollView`. Необработанные перетаскивания основной кнопкой остаются доступны для выделения текста в транскрипте. Ссылки OSC 8 важнее областей нажатия, которые их содержат.

В обычном режиме мышиный ввод остаётся терминалу, потому что историей прокрутки владеет терминал. Для каждого взаимодействия держите клавиатурный путь, даже когда доступен мышиный ввод в полноэкранном режиме.

## Используйте собственные экраны и оверлеи

`ctx.ui.custom()` временно передаёт одному компоненту управление интерактивной областью и завершается, когда компонент вызовет переданную функцию завершения.

### Соберите минимальный собственный экран

Это полное расширение показывает жизненный цикл собственного компонента: отрисовка в пределах переданной ширины, использование переданных привязок клавиш, сброс кэшированного вывода после изменения состояния, запрос перерисовки и завершение через `done()`.

```ts
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";
import { truncateToWidth } from "@earendil-works/pi-tui";

export default function (pi: ExtensionAPI) {
  pi.registerCommand("pick-target", {
    description: "Pick a deployment target",
    handler: async (_args, ctx) => {
      if (ctx.mode !== "tui") {
        ctx.ui.notify("pick-target requires interactive mode", "error");
        return;
      }

      const choices = ["development", "staging", "production"];
      const selected = await ctx.ui.custom<string | undefined>((tui, theme, keybindings, done) => {
        let selectedIndex = 0;
        let cachedWidth: number | undefined;
        let cachedLines: string[] | undefined;

        const invalidate = () => {
          cachedWidth = undefined;
          cachedLines = undefined;
        };

        return {
          render(width: number): string[] {
            if (cachedLines && cachedWidth === width) return cachedLines;

            cachedWidth = width;
            cachedLines = [
              theme.fg("accent", "Choose a deployment target"),
              ...choices.map((choice, index) => `${index === selectedIndex ? "> " : "  "}${choice}`),
              theme.fg("dim", "up/down move, enter selects, escape cancels"),
            ].map((line) => truncateToWidth(line, width));
            return cachedLines;
          },
          handleInput(data: string): void {
            if (keybindings.matches(data, "tui.select.up")) {
              selectedIndex = (selectedIndex - 1 + choices.length) % choices.length;
            } else if (keybindings.matches(data, "tui.select.down")) {
              selectedIndex = (selectedIndex + 1) % choices.length;
            } else if (keybindings.matches(data, "tui.select.confirm")) {
              done(choices[selectedIndex]);
              return;
            } else if (keybindings.matches(data, "tui.select.cancel")) {
              done(undefined);
              return;
            } else {
              return;
            }

            invalidate();
            tui.requestRender();
          },
          invalidate,
        };
      });

      if (selected) ctx.ui.notify(`Selected ${selected}`, "info");
    },
  });
}
```

Этот компонент не показывает текстовый курсор, поэтому `Focusable` ему не нужен. Компонент, внутри которого есть `Input` или `Editor`, обязан реализовать `Focusable` и передавать этому дочернему элементу своё значение `focused`.

Собственные компоненты не сообщают pi, что тот ждёт пользователя, потому что `ctx.ui.custom()` размещает также загрузчики и другой неблокирующий интерфейс. Когда встроенный компонент ждёт ответа, передайте `blocked: { kind: "question", message: "Pick a color" }` — тогда терминалы с поддержкой [программного статуса](https://pi.dev/docs/latest/terminal-setup#program-status) покажут pi ожидающим, пока компонент виден. `kind` бывает `"question"`, `"permission"` или `"auth"`. Оверлеи эту опцию игнорируют.

Передайте `overlay: true`, чтобы рисовать поверх существующего содержимого. Опции оверлея управляют размером, точками привязки, смещениями, полями и поведением при смене размера окна. Через дескриптор оверлея можно менять фокус или временно прятать и показывать оверлей с помощью `setHidden()`, пока взаимодействие активно.

Оверлей в фокусе сохраняет за собой ввод при обычных перерисовках. Если во время видимого оверлея ввод должен получать другой компонент, фокус нужно явно освободить или перенаправить через дескриптор.

Считайте каждый экземпляр собственного компонента принадлежащим одному взаимодействию. Начинаете взаимодействие заново — создавайте новый экземпляр.

Завершайте взаимодействие функцией, переданной фабрике компонента. Она завершает промис `ctx.ui.custom()` и уничтожает компонент. Не вызывайте `OverlayHandle.hide()` у оверлея, созданного через `ctx.ui.custom()`.

Позиционирование, стекирование, фокус, реакцию на размер окна и анимацию смотрите в [`overlay-qa-tests.ts`](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/examples/extensions/overlay-qa-tests.ts).

## Правильно применяйте темы

Используйте тему, переданную колбэку расширения или компонента. Помощники темы собирают строки с ANSI-стилями для семантических цветов: акцент, приглушённый текст, успех, предупреждения, ошибки, вывод инструментов и Markdown.

Чтобы совместить цвета переднего плана и фона с текстовыми атрибутами, используйте `theme.style()`:

```ts
return new Text(
  theme.style("Done!", {
    fg: "success",
    bg: "toolSuccessBg",
    bold: true,
  }),
  0,
  0,
);
```

Цвет в стиле — это либо семантический токен темы, либо конкретный `Color`. Токены переднего плана принимаются в `fg`, фоновые — в `bg`; чтобы взять цвет токена на противоположной позиции, передавайте его конкретный цвет, например `{ fg: theme.colors.userMessageBg }`. Конкретные цвета доступны через `theme.colors`, а для цветовых вычислений берите такие помощники, как `mixColors()` из `@earendil-works/pi-tui`. Токены, которые тема оставляет терминальными по умолчанию, рисуются цветом самого терминала; `theme.colors` показывает цвет, который терминал о себе сообщил, или догадку, если он ничего не сообщил. Через `theme.appearance` (`"dark"` или `"light"`) решают, например, осветлять цвет или затемнять. Pi конвертирует результат в truecolor или 256 цветов по возможностям терминала. Токены темы конвертируются один раз на тему; конкретные цвета по возможности считайте вне пути отрисовки.

Прежние помощники `theme.fg()` и `theme.bg()` остаются доступны для нанесения одного семантического цвета.

Не храните постоянно строки с цветами темы, если `invalidate()` не перестраивает их. Смена темы очищает кэши отрисовки, но не может убрать старые ANSI-цвета, вшитые в состояние приложения.

Колбэкам темы, которые вычисляются во время отрисовки, особая перестройка не нужна. Компоненты без состояния могут собирать оформленный вывод на каждую отрисовку.

Палитры терминала создавайте в [темах](https://pi.dev/docs/latest/themes). Для Markdown, который должен совпадать с активной темой приложения, используйте `getMarkdownTheme()` из Pi.

## Держите отрисовку отзывчивой

Отрисовка лежит на интерактивном пути. Кэшируйте дорогую разметку и подсветку по ширине и содержимому и очищайте этот кэш из `invalidate()`.

Держите вид по умолчанию компактным, а подробности открывайте разворачиванием или отдельным экраном. При своей отрисовке инструментов обрабатывайте частичные результаты и повторно используйте предыдущий компонент, когда его можно безопасно обновить.

Для диагностики проблем отрисовки снимайте сырой ANSI-поток через `PI_TUI_WRITE_LOG`. Проверяйте узкие ширины, широкие символы, события изменения размера, смену темы, переходы фокуса и оба режима — обычный и полноэкранный.
